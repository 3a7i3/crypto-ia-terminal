# P4 external pure readers: API boundary v0

SOURCE_ONLY / CONTRACT_BEFORE_CODE. Main baseline 1e026bf934ccff69439b0e5856e8f0a3f5e60edb. Refines P4_EXTERNAL_EVIDENCE_FORMATS_V0.md and OPERATION_LEDGER_INSPECTION_CONTRACT_V0.md; pinned P1 files unchanged.

APIs: project_fault_log(raw: bytes, lab_id: str) -> FaultProjection; project_installed_trust(policy_raw: bytes, history_raw: bytes, lab_id: str) -> TrustProjection. The lab id is an expected label, not acquired provenance. Inputs are bytes only; paths, callbacks, clocks, roots installed by caller assertion, or action arguments are not accepted. Public outputs are frozen dataclasses containing only scalars, bytes and tuples of frozen summaries, never mutable caller-owned JSON.

All outputs retain accepted=false, provenance/durability/external_facts=NOT_EVALUATED. STRUCTURAL_ONLY and STRUCTURAL_MATCH are lexical consistency observations, not permission, source authenticity, valid root key material, validated rotation, storage health or durable state. Empty bytes mean an empty supplied fault log only, never a verified healthy/missing machine file. Invalid input, unsupported version, corruption or limit failure discards every usable prefix; no ACK, repair or fallback.

FaultProjection retains canonical entry bytes, all sticky FaultClaim summaries, TerminationClaim summaries and pending set-aside operation labels. Fault/resource metadata are claims, never trusted opened-resource mappings. /1 termination evidence validates the complete embedded observation, own hash, operation/status/count binding and closed field invariants; it is historical and is never compared against a current ledger snapshot by this parser. /0 digest-only termination evidence remains REFERENCE_UNRESOLVED; a future join must not infer a terminal override from it without separately acquired bound evidence. /0 is not silently rewritten as /1. Neither format grants resume/admission/execution.

The fault reader checks same-operation child/attempt binding, prior exact OPERATION_LOG fault reference, one termination per operation, and external set-aside BEGIN/DONE ordering with D3 provenance. Faults remain sticky after termination. An action fault between set-aside BEGIN/DONE blocks completing that action in this slice; a future restore gate is not implemented. Actual expected identity bytes, filesystem/link checks, cold-read provenance, ledger acquisition and authorization remain external obligations. A structurally plausible SET_ASIDE entry does not execute or approve a move.

TrustProjection retains canonical policy bytes and immutable history tuples only for a full structural head match. It checks LAB_TEST and expected lab labels, canonical full-root digest, installed pin/floor and last-history equality, increasing history versions and nondecreasing floors. Nested root/issuer/key objects are closed and lexically checked, but public key curve validity, key-id derivation, issuer authorization, trust semantics and monotone material changes across roots still require existing colony_trust.check_root/installation checks in the later join. No import of colony_trust, colony_registrar or colony_lab from these pure modules.

Limits follow #495: fault log4096lines/16KiB-per-line/64MiB total; history4096lines/1024bytes-per-line/4MiB total; policy65536bytes. Per-line limits include newline; policy has none. Reuse existing strict bounded JSON decoder (32containers/128digit integer tokens) without changing its operation-log defaults. All bytes are consumed before a successful structural result. Failure errors contain only fixed codes, no raw values.

This slice implements no filesystem adapter, evidence acquisition join, trust installer, durable writer, restore/quarantine/termination action, root/key creation or individual. P4 remains incomplete; P5/P6 and runtime authorization are unaffected. #286 ACTIVE, no VPS/deployment/runtime change.
